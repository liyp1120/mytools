# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository layout

A collection of self-contained browser tools. Each tool is a single file with inline CSS/JS (or, for the terminal, an embedded HTML page). There is no build step, package manager, test suite, lint config, or CI.

- `markdown-viewer-editor/mve.html` — "余白" (Yubai), a Chinese-language offline Markdown editor/viewer (~3,300 lines, all CSS/JS inline).
- `html-terminal/hterminal.py` — self-contained Python launcher: starts `ttyd`, serves the embedded multi-tab wrapper page, and opens it.

## Running

No build. Serve the repo (or open files directly; `localStorage` works from `file://` too):

```bash
python3 -m http.server 8000
# http://localhost:8000/markdown-viewer-editor/mve.html
```

Web terminal:

```bash
./html-terminal/hterminal.py   # or: python3 html-terminal/hterminal.py
```

The launcher starts `ttyd -W -i 127.0.0.1 -p 7681 bash` (logs to `/tmp/ttyd.log`) unless that port is already listening, serves the embedded wrapper page over a random localhost port, and opens it. `Ctrl+C` stops the page server and any ttyd process the launcher started (an already-running ttyd is left alone). `hterminal.py` is the only file needed; the wrapper HTML lives in `PAGE_HTML`.

No automated tests or linting exist; verify changes manually in a browser.

## markdown-viewer-editor architecture

One IIFE in one file, sectioned by `/* ---------- Name ---------- */` comments. A central `state` object plus the `<textarea id="editor">` are the source of truth — no framework and no contenteditable.

**Render pipeline:** editor `input` → `scheduleRender()` (55 ms debounce) → `renderNow()` → `renderMarkdown(source)` → `parseBlocks()` → HTML injected into `#article`. `renderMarkdown()` also rebuilds:

- `state.headings` — `{level, plain, id, line, offset}` for the outline.
- `state.lineStarts` — per-line character offsets, used to map headings between editor and preview.

**Markdown support is custom** (no library): ATX/setext headings, fenced and indented code, blockquotes (recursive `parseBlocks`), nested ordered/unordered and task lists, pipe tables with alignment, hr, and inline code/images/links/strong/em/del. When adding syntax, update `isBlockStart()` (block detection), `parseBlocks()` (block rendering), and `renderInline()`/`formatInline()` (inline) together. `renderOutline()` and `updateStats()` depend on the heading object shape.

**Inline-safety invariants:** `extractCodeSpans()` replaces code spans with `\x00C<n>\x00` tokens and links/images with `\x00L<n>\x00` tokens so emphasis never parses inside them; `escapeHtml()` escapes text; `safeUrl()` allowlists `http`/`https`/`mailto`/`tel` (plus `data:image/*` for images). Preserve these when touching inline rendering.

**Editor ↔ preview sync:** heading navigation scrolls the editor using a hidden `.editor-mirror` element to measure text height (`measureEditorCharTop()`), and scrolls the preview via `data-line` attributes on `h1`–`h3`. Outline highlighting follows preview scroll (`activeOutlineFromPreview()`) or the editor caret line.

**View modes:** `body[data-mode="write|split|read"]` drives a CSS grid layout. `state.requestedMode` is persisted; `effectiveMode()` forces `write` on mobile (<760 px). The outline rail becomes a drawer below 1180 px in split mode and below 760 px generally.

**Persistence:** `localStorage` only, keys all `yubai.*` (`.doc.v1`, `.theme.v1`, `.mode.v1`, `.rail.v1`). One document, autosaved 320 ms after typing and flushed on `visibilitychange`/`beforeunload`; `storage` swallows quota/security errors and `setSaveState()` surfaces saving/error in the top bar. Import/export are client-side (5 MB cap, `.md`/`.markdown`/`.txt`). The sample text lives in `<script type="text/plain" id="welcomeSource">` and appears only when no saved document exists.

**Theming/design:** CSS custom properties on `:root` and `html[data-theme="dark"]`; print styles in `@media print`. All user-facing copy is Chinese — keep new strings Chinese to match. Keyboard handling is split: global shortcuts in `handleGlobalKeydown()`, editor-only list continuation/Tab indentation in `handleEditorKeydown()`, and displayed shortcut labels generated by `populateShortcuts()` (`⌘` on macOS, `Ctrl` elsewhere).

## html-terminal architecture

- `hterminal.py` is self-contained: `PAGE_HTML` holds the wrapper page; `start_ttyd()` reuses an existing listener on `127.0.0.1:7681` or spawns `ttyd -W -i 127.0.0.1 -p 7681 bash` in its own session; `start_page_server()` serves `PAGE_HTML` at `/` on a random `127.0.0.1` port. `Ctrl+C`/SIGTERM shuts down the page server and terminates a ttyd process the launcher started (`start_new_session` + `killpg`); a pre-existing ttyd is left running.
- The wrapper renders one tab per terminal: every tab creates its own iframe to the same ttyd origin, and ttyd spawns a separate process/PTY per WebSocket client. Inactive panes stay loaded with `visibility: hidden`, so sessions survive tab switches; closing a tab removes its iframe (killing that session), and the last tab cannot be closed. The iframe origin is fixed at `http://127.0.0.1:7681`, so ttyd and the browser must run on the same machine.
- `-W` allows input (write access), and `-i 127.0.0.1` binds to localhost only. There is no authentication or reverse proxy; do not expose the ttyd port publicly without adding one.
